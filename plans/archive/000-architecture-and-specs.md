# План #000: Проєктування архітектури, специфікації та правил агентів

- **Статус:** `Закрито / В архіві`
- **Модуль / Область:** `docs` / `core` / `finance`

## 1. Мета задачі
Зафіксувати єдину технічну, продуктову та комерційну архітектуру KasaBot перед початком написання коду, а також налаштувати правила роботи AI-агентів із системою планування та архівування.

## 2. Прийняті архітектурні рішення
- **Mobile-First (Capacitor + PWA + Desktop Web з одного коду `web/`):** головний сценарій — керування однією рукою з телефону («Пульт» з великою кнопкою мікрофона + вібро-відгук `Haptics` + офлайн-черга в `IndexedDB`).
- **Незалежність від Telegram:** веб/мобільний додаток є головною точкою входу (Email + Password -> JWT). Telegram є опціональним каналом (`telegram_link_tokens`).
- **Мультитенантність (`Workspaces`):** підтримка кількох просторів («Мій ФОП», «Сімейний бюджет») та запрошення партнерів.
- **Фіксований довідник категорій (`fin_categories`):** динамічна передача категорій воркспейсу як `enum` у JSON Schema для Gemini.
- **Оптимістичне збереження («за 3 секунди»):** збереження одразу без діалогів підтвердження + кнопка «Скасувати».
- **Монетизація:** 14 днів Trial, м'яке блокування (Read-Only + `402 Payment Required`), денні квоти на AI (`429 Too Many Requests`), перевірка `Capacitor.isNativePlatform()` для правил App Store.
