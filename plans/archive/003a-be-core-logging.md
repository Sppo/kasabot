# План #003a: [BE-Core] Логування у файли по днях, окремий файл помилок та `error_id`

- **Статус:** `Закрито / В архіві`
- **Дата:** 2026-11-20
- **Модуль / Область:** `core`

## 1. Мета задачі
Щоб можна було розібратись, що сталося, не читаючи логи в терміналі:
- усі події пишуться у файл за днем (`logs/app-YYYY-MM-DD.log`);
- помилки додатково пишуться в окремий файл за днем (`logs/errors-YYYY-MM-DD.log`);
- кожна помилка має короткий `error_id`, а кожен запит має `request_id`, щоб за скороченим рядком (наприклад, із Telegram-сповіщення) агент або розробник міг знайти повні точні логи у файлі.

Скорочені сповіщення в Telegram залежать від Telegram-ядра (`bot.go`) і робляться в Плані #004. Цей план готує для них `error_id` і хук.

## 2. Файли для створення або зміни
- `internal/core/logger.go` — створення `slog`-логера (JSON), запис у два файли по днях, ротація та видалення старих файлів, генерація `error_id`, HTTP-middleware з `request_id`.
- `internal/core/logger_test.go` — тести.
- `internal/core/config.go` та `internal/core/config_test.go` — нові параметри логування.
- `.env.example` — нові змінні з коментарями українською (одиниці та рекомендовані значення).
- `.gitignore` — **лише пропозиція** додати `logs/` (без окремого підтвердження не змінюю).

## 3. Покроковий план реалізації
1. [x] **Конфіг:** додати в `Config` та `config.go` параметри `LOG_DIR` (каталог логів, за замовчуванням `logs`) та `LOG_RETENTION_DAYS` (скільки днів зберігати файли). Дефолти як іменовані константи, валідація, коментарі в `.env.example`. День файлу визначається за `DEFAULT_TIMEZONE`.
2. [x] **`logger.go`:** `slog` з JSON-обробником, що пише в `app-<день>.log`. Файл змінюється при зміні дня. Записи рівня ERROR додатково йдуть у `errors-<день>.log`. Запис у stdout дублюється.
3. [x] **Ротація:** при старті та раз на добу видаляти файли логів старші за `LOG_RETENTION_DAYS`. Обробляти помилки без паніки і без втрати основного логування.
4. [x] **`error_id`:** функція генерації короткого ідентифікатора (8 hex-символів) і запис його в поле `error_id` разом з `request_id`, `error_code`, `workspace_id`, `user_id`.
5. [x] **HTTP-middleware:** присвоює `request_id`, логує метод, шлях, статус і тривалість (`log/slog`), без тіла запиту та без заголовків із токенами. Підключення в роутер робиться в Плані #004 (`app.go`).
6. [x] **Хук для сповіщень:** простий інтерфейс чи функція, яку логер викликає при ERROR (наразі порожня), щоб План #004 міг підключити Telegram без зміни логера.
7. [x] **Тести:** запис у два файли, розділення день за днем (через підставлений годинник), видалення старих файлів, наявність `error_id` у обох файлах, відсутність секретів і тіла запиту.
